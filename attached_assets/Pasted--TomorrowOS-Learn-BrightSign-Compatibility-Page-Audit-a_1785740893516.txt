# Objective

Build a transparent BrightSign platform page that tells developers:

* what TomorrowOS supports;
* what has been physically tested;
* which firmware requirements are known;
* what the player runtime handles;
* how the installation and pairing flow works;
* which media and platform limitations matter;
* which combinations still require validation;
* where implementation documentation and source code live.

The page must help a developer decide whether their BrightSign hardware is appropriate for TomorrowOS without overstating certification.

---

# Critical product-language rule

The page must distinguish between:

## Supported series

A player generation that the TomorrowOS runtime is designed to support.

## Tested model

An exact model that has been run through physical TomorrowOS testing.

## Tested firmware

An exact BrightSign OS build that has completed the validation workflow.

## Media certified

A media profile that has passed defined playback and recovery testing on a specific model and firmware.

Do not use these terms interchangeably.

Do not use “certified” unless there is a completed supporting result.

# Known provisional position to verify

The following information has been identified in existing TomorrowOS planning and review materials.

Treat it as provisional until verified against the current BrightSign repository and website/docs source:

* BrightSign Series 3, 4, 5 and 6 are within the supported scope.
* BrightSign Series 3 requires BrightSign OS 9.1.140 or later.
* BrightSign Series 3 4K H.264 is not supported.
* Validated 1080p H.264 media is the recommended Series 3 pathway.
* Known physical test models include:

  * XD233 — Series 3
  * HD225 — Series 5
  * HD226 — Series 6
* Series 4 support is claimed at series level, but a named physical Series 4 test device may not yet be recorded.
* Exact tested OS builds may still be incomplete in the public validation data.
* Existing platform materials indicate native-player / TomorrowOS Runtime playback.
* The current BrightSign documentation needs a stronger quick-start layer.

Verify every point.

If repository evidence conflicts with these statements, report the conflict and use the more conservative public wording.
