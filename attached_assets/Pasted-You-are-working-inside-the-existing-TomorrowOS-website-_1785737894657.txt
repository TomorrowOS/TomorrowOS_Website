## Project goal

TomorrowOS currently has three separate information layers:

1. tomorrowos.org
   Explains the product and directs users toward the appropriate journey.

2. docs.tomorrowos.org
   Contains implementation documentation, setup instructions, API references and technical product documentation.

3. GitHub
   Contains source code, releases, issues, discussions and contribution workflows.

The proposed `/learn` section will be a separate discovery and education layer.

Its purpose is to answer broader questions such as:

* How do I build a digital signage CMS?
* What is a digital signage SDK?
* How does a digital signage API work?
* What is headless digital signage?
* How do Samsung Tizen and BrightSign signage players work?
* How can a product team build and own digital signage software?

It must not duplicate detailed implementation documentation already contained within Mintlify or GitHub.

The intended relationship is:

Learn → educate
Documentation → implement
GitHub → inspect, contribute and develop
