Refine all copyable prompt, command, URL and configuration-value blocks across the existing TomorrowOS onboarding experience.

This is an existing working application.

Do not rebuild the onboarding.
Do not change routes, step order, completion logic, localStorage keys, commands, URLs, prompts or configuration values unless explicitly instructed below.
Do not change the approved page layouts or broader design system.

The current copyable content blocks use pale-grey containers and faint copy icons. They blend into the page and do not clearly communicate:

- What should be copied
- Where it should be pasted
- Whether copying succeeded
- Whether the content is a prompt, command, URL or variable name

The objective is to create one clear, consistent and reusable copy-action pattern across the full onboarding journey.

CopyActionBlock

CopyActionBlock {

Do not duplicate separate copy implementations across every guide.

==================================================
4. VISUAL HIERARCHY
==================================================

For primary prompts and terminal commands, use a high-contrast code panel.

Default styling:

- Black or near-black background
- White or very light code text
- JetBrains Mono
- Approximately 14–15px text
- Comfortable 18–22px padding
- Approximately 8px radius
- No heavy shadow
- Clear separation from surrounding content
- Horizontal scrolling for long commands
- Preserve whitespace where required

Above the panel, show a small contextual label.

Examples:

PROMPT FOR v0

COMMAND FOR YOUR TERMINAL

CMS URL

ENVIRONMENT VARIABLE

Do not use generic labels such as:

CODE

COPY THIS

unless no more specific description is available.

==================================================
5. EXPLICIT COPY BUTTON
==================================================

Replace faint standalone copy icons on important blocks with an explicit action.

Use context-specific labels:

Prompt:
Copy prompt

Terminal command:
Copy command

URL:
Copy URL

Environment-variable name:
Copy variable name

Code example:
Copy code

Configuration value:
Copy value

The button may include the existing copy icon, but visible text must remain present on primary copy blocks.

Recommended position:

- Top-right inside the block header, or
- Right side of a compact header row directly above the code content

Do not allow the button to overlap long content.

==================================================
6. COPIED FEEDBACK
==================================================

After a successful copy, temporarily change the button text.

Examples:

Copied

Copied — paste into v0

Copied — run in your terminal

Copied — add to Vercel

Use the destination-specific message when the destination is known.

Requirements:

- Feedback remains visible for approximately 1.5–2.5 seconds
- Announce success using an accessible live region
- Do not rely only on colour
- Do not cause the block width to jump significantly
- Restore the original label automatically

When copying fails:

Show:

Could not copy — select the text manually.

Do not fail silently.

==================================================
7. DESTINATION INSTRUCTION
==================================================

Where the content must be pasted into another tool, add a concise instruction beneath the block.

Examples:

v0:

Paste this into the main v0 prompt field, then submit it.

Replit:

Paste this into Replit Agent, then follow the questions one at a time.

Terminal:

Run this command in your local terminal.

Vercel:

Add this variable in Project Settings → Environment Variables.

CMS URL:

Save the public HTTPS URL shown after publishing.

Keep this instruction outside the copied content unless it genuinely belongs in the prompt.

9. SECURITY WARNING REFINEMENT
==================================================

Preserve the current security warning.

Do not remove or weaken:

- Do not paste prompts into public code files
- Do not paste prompts into environment-variable values
- Do not paste prompts into Vercel project settings
- Do not paste prompts into a database console
- Do not paste passwords, API secrets or storage tokens into v0

However, rebalance the visual hierarchy so the primary copy action is still easy to find.

Recommended adjustment:

- Keep the warning above the prompt
- Reduce excessive internal spacing where present
- Use a restrained pale-warning background
- Keep strong contrast
- Do not make it taller than necessary
- Keep the actual prompt block visually prominent immediately beneath it

Do not turn the warning into a modal or blocking confirmation.

==================================================
10. LIGHT BLOCK VARIANT
==================================================

Not every copied value needs a black code panel.

Use a light variant for secondary values such as:

- Variable names
- Short IDs
- Public URLs
- Non-primary configuration values

Light variant:

- Very light neutral-grey background
- 1px neutral border
- Dark JetBrains Mono text
- Explicit copy button
- Same copied feedback
- Approximately 8px radius

Do not use the light variant for primary setup prompts when stronger emphasis is needed.
