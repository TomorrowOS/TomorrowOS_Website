You are building an interactive front-end MVP for the TomorrowOS onboarding experience.

This is a design-validation prototype that will be reviewed by the TomorrowOS team, designers and non-technical testers before the final production onboarding is built.

The objective is to create the clearest possible onboarding journey for:

1. A non-technical or low-code user building through Replit Agent.
2. A technical developer building through the TomorrowOS CLI and terminal.

Both journeys must eventually merge into the same player installation, device pairing and first-content deployment flow.

Do not redesign the TomorrowOS brand.

Use the attached current onboarding page as the primary visual reference. Preserve its overall structure, visual language and simplicity, while improving clarity, interaction, error recovery and branching.

==================================================
2. PRODUCT OBJECTIVE
==================================================

Create a polished, responsive and interactive TomorrowOS onboarding MVP.

The user should always understand:

- Where they are.
- What they are doing.
- Which platform they are currently using.
- What information they need.
- Where to find that information.
- Where to paste it.
- Whether the step worked.
- How to recover when something fails.
- What happens next.

The experience must never require the user to Google how to continue.

The experience should feel like:

Choose a path
→ follow clear steps
→ connect required services
→ verify everything
→ publish
→ pair a screen
→ deploy content

It must not feel like several unrelated technical systems stitched together.
