Do not use the wording:

`Coming Soon`

* Production Ready
* Available
* In Development
* Platform Validation
* Community Contribution
* Planned

For each state, specify:

* Meaning
* Visual treatment
* Whether the card is clickable
* Destination behaviour
* Whether the route should exist
* Whether the route should be indexable
* Whether it should appear in navigation
* Appropriate CTA wording

Important:

Do not create placeholder article routes merely because a card exists.

Where content does not yet exist, the preferred behaviour is usually:

* Show the resource on `/learn`
* Explain its current maturity
* Link to the best existing documentation, GitHub discussion, roadmap or supported-platform page
* Avoid publishing an empty or low-value route

Recommend exceptions only where a meaningful standalone status page would genuinely help users.
