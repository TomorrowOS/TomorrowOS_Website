# Resource maturity model

Use exactly these statuses:

* `production-ready`
* `available`
* `in-development`
* `platform-validation`
* `community-contribution`
* `planned`

Visible labels:

* Production Ready
* Available
* In Development
* Platform Validation
* Community Contribution
* Planned

Rules:

## Production Ready

Meaning:

The resource or platform is shipped, supported and validated for its stated scope.

Behaviour:

* Clickable
* Links to a live page, Learn article, guide or documentation
* Badge may be hidden or visually subtle

CTA:

* Read the guide
* View documentation
* View platform

## Available

Meaning:

Useful material or capability exists today.

Behaviour:

* Clickable
* Links to a genuine existing destination
* Badge may be hidden or neutral

CTA:

* Read
* View documentation
* Explore

## In Development

Meaning:

The resource is actively being built or documented.

Behaviour:

* Clickable only when there is a useful current destination
* Link to GitHub discussion, roadmap, existing guide or documentation
* Never link to an empty Learn article shell

CTA:

* Follow progress
* View current documentation

## Platform Validation

Meaning:

Support or documentation is undergoing hardware, firmware or workflow validation.

Behaviour:

* Link to the compatibility page, tested-platform information or existing guide
* Never imply full production support

CTA:

* See validation status

## Community Contribution

Meaning:

The resource is suitable for community contribution.

Behaviour:

* Link to GitHub Discussions, contributing information or an appropriate repository
* Must not imply that the guide already exists

CTA:

* Contribute

## Planned

Meaning:

The resource is planned but not currently available.

Behaviour:

* It must still link somewhere useful, such as a roadmap, relevant documentation overview or GitHub discussion
* If no useful destination exists, omit the card rather than make it dead
* Never create a placeholder article route solely for the card

CTA:

* View roadmap
* Follow development

Never use:

`Coming Soon`

No card may be visually disabled or unclickable dead weight.

Every visible card must lead somewhere useful and truthful.
